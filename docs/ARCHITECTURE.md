# Arquitetura

O endpoint público é `POST /mcp`. O Worker cria um servidor MCP e transporte por troca HTTP a cada request. A configuração usada é `legacy: 'reject'` e `responseMode: 'json'`; não existem sessões de transporte, `Mcp-Session-Id`, SSE, WebSocket, stdio, `/sse` ou `createLegacyMcpHandler`.

O protocolo implementado é MCP `2026-07-28`. O SDK v2.3.1 mantém uma constante histórica de compatibilidade para a era 2025, então o Worker publica explicitamente a revisão 2026 no health check e usa a entrada moderna do `createMcpHandler`. Requests MCP devem conter a versão e os cabeçalhos de roteamento exigidos pela revisão (`MCP-Protocol-Version`, `Mcp-Method` e `Mcp-Name`).

O OAuth Provider do Cloudflare é usado no mesmo Worker. Ele responde descoberta, registro compatível, Authorization Code + PKCE S256, refresh e revogação. O recurso canônico é `https://app.wapilot.com.br/mcp`; o hostname `workers.dev` permanece provisório durante a transição. A rota `/authorize` fica sob uma aplicação Cloudflare Access separada, com One-time PIN e allowlist de `luccamordente@gmail.com` e `heitorsalazar@gmail.com`. O Access autentica o navegador; o OAuth Provider emite o token MCP. A assertion do Access nunca é aceita como token MCP.

D1 guarda usuários, conexões, auditoria e eventos de webhook. A conexão padrão é persistida por usuário em `whatsapp_connections.is_default`; estados de onboarding podem permanecer em `whatsapp_connections.connection_state`, mas nenhuma consulta de status usa esse campo como fonte de verdade. `list_connections` consulta diretamente `GET /instance/all` no Evolution Go com a chave administrativa e não persiste o resultado; `connection_status` e a UI consultam `GET /instance/status` diretamente no Evolution Go. A primeira conexão recebe o papel padrão automaticamente, a exclusão da conexão padrão promove a conexão restante mais antiga e a UI só altera o padrão por ação explícita. As ferramentas MCP que operam uma conexão aceitam o UUID interno opcionalmente: quando omitido, o Worker exige exatamente uma conexão padrão; um UUID informado tem prioridade. Ausência de padrão ou múltiplos padrões produz erro explícito. KV é reservado ao estado do OAuth Provider. O token de cada instância é cifrado com AES-GCM usando `TOKEN_ENCRYPTION_KEY` em Secret. O Worker resolve `(user_id, connection_id)` antes de descriptografar o token e enviar `apikey` ao Evolution Go.

`/connections` é a superfície autenticada do dashboard e do onboarding. Os endpoints same-origin `/connections/data`, `/api/connections/provision`, `/api/connections/:id/status`, `/api/connections/:id/qr` e `/api/connections/:id/default` sustentam a troca de contexto, o provisionamento, a renovação do QR e a verificação do estado sem expor tokens de instância.

`list_messages` consulta diretamente `GET /message/search?q=&limit=`. Essa busca depende de `DATABASE_SAVE_MESSAGES=true` no Evolution Go e não substitui uma listagem de chats: o fork não expõe endpoint de listagem de chats. O webhook continua recebendo eventos para integração e auditoria operacional: usa um segredo opaco por conexão, verifica a instância, remove o token do payload e deduplica por `(connection_id, event_name, message_id)`.
